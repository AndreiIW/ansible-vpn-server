# Ansible Playbooks

Данный Ansible Playbooks сможет полностью настроить ваш сервер, установив на наго следующее ПО

 - AmneziaWG с web админкой управления пользователями; [Проект AmneziaWG Installer](https://github.com/wiresock/amneziawg-install) 
 - Прокси сервер telemt для Telegram; [Проект telemt](https://github.com/telemt/telemt)

Я взял их код за основу и написал этот Ansible Playbooks. Ребятам вырожаю огромную благодарность за их труд. Ansible playbook-и были написаны и протестированны для ОС Ubuntu 24.04.

## Требования к управляющей системе

Данный Ansible Playbooks был написан на Ansible 2.21.0, однако скорее всего playbook-и запустятся и на других версиях Ansible. Так же для корректной работы модуля ansible.utils.ipaddr нужна дополнительная Python библиотека netaddr. Установить на управляющем компьютере можно с помощью команды:

```shell
sudo apt install python3-netaddr
```
Данный модуль нужен для того, что бы определить каким ip адресом мы пользуемся, публичным или приватным, из bogon сетей.

## Логика работы данных playbook-ов

Все playbook-и разбиты на логические разделы. Предпологается что у нас есть только что созданная Ubuntu 24.04 от хостинга или виртуальная машина. А большенство хостингов при создании машины выдают машинку с единственным root пользователем. Что **очень**, очень небезопасно. Поэтому первое что надо сделать, это создать вашего пользователя.

Ну а дальше после всех установок, нужно обезопастить сервер. Закрыть подключения root по SSH. Сделать подключение по SSH исключительно по ключу. Для большей защиты и удобства автоматический блокировки fail2ban для Nginx нужно закрыть web админку AmneziaWG дополнительной базовой авторизации Nginx (.htpasswd). Ну и конечно закрыть все порты с помощью iptables и открыть исключительно рабочие порты.

## Начальная подготовка

Для начала надо открыть файл hosts и записать ip адрес своего сервера, который будем настраевать. Потом в папку key нужно записать свой публичный ключ для своей учётной записи.
И последнее, надо заполнить файл с переменными group_vars/all.yml

## Запуск подготовки сервера

После указания ip адреса сервера, вашего публичного ключа и заполнения переменных, можно начинать. Начинаем с первого шага, это безовой, подготавительная настройка.

```shell
ansible-playbook 1-prepare.yml -u root --ask-pass
```
Где:
* prepare.yml - запускает роль базовой подготовки
* -u имя пользователя root, от которого запускаем playbook

Тут мы поставим самые базовые программы, создамим вашего пользователя.

## Настройка базовых программ сервера

```shell
ansible-playbook 2-base-setup-server.yml
```
Тут уже при запуске не нужно указывать пароль, так как дальше все playbook-и будут запускаться от вашего пользователя, созданный ранее. Тут мы настроим SSH, установим русский язык на сервер, да у программы journald уменьшим количество логов до 3-ёх дней. Так как обычно для VPN арендуют машинки с маленькими дисками, так что забивать их логами не очень разумно.

Кстати у каждой роли есть свой тэг, что бы установить только конкретный пункт. В примеру запуск команды

```shell
ansible-playbook 2-base-setup-server.yml -t ssh
```
запустит исключительно настройку SSH. Всё остальное будет игнорированно.

## Установка VPN и MTProxy

```shell
ansible-playbook 3-vpn-and-mtproxy.yml
```
На этом шаге мы установим AmneziaWG, web управление пользователями и MTProxy для Telegram telemt. После этого шага остаётся только зайти на сервер и получить ссылку для Telegram выполнив команду

```shell
 curl -s http://127.0.0.1:9091/v1/users | jq -r '.data[] | "[\(.username)]", (.links.classic[]? | "classic: \(.)"), (.links.secure[]? | "secure: \(.)"), (.links.tls[]? | "tls: \(.)"), ""'
```
Подробнее можно узнать в [репозитории telemt](https://github.com/telemt/telemt) . Для управления пользователями AmneziaWG можно зайти по ip адресу сервера или по его доменному имени.

## Настройка защиты сервера
 
```shell
ansible-playbook 4-security-server.yml
```

Тут мы закрываем все порты с помощью iptables. Nginx переводим в SSL режим. Если у нас сервер имеет доменное имя или публичный ip адрес, то SSL сертфиикаты получим с помощью Let's Encrypt. Если сервер для тестирования запустили в локальной сети с приватным ip адресом, то будет сгенерирован самоподисанный сертификат. Ну и в конце запускаем fail2ban который будет блокировать злодеев, сканирующие SSH и Nginx.

Блокировку fail2ban я настроил так:

- `SSH`: Обычные боты совершают несколько попыток подбора пароля, получают бан на 1 час, покорно ждут его окончания и через час возвращаются снова. Если какой-то бот за эти сутки успел схватить бан 5 раз, то тюрьма recidive распознает его как злостного рецидивиста и отправляет в глубокий бан на неделю.
- `Nginx`: Обычные пользователи, которые случайно опечатались в пароле, не улетят в бан сразу, так как у них есть 10 попыток за 5 минут. А вот сканеры которые делают по 30–50 запросов за пару секунд этот лимит в 10 попыток пробьют мгновенно и улетят в бан сразу на целый день.
